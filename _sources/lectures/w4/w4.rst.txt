Week 4: The Memory Model and the Memory Hierarchy
=================================================

This week we will look atg where every byte of a running program lives, and how to find
the memory bugs C won't catch. We then follow an address from your code to
real RAM through registers, caches, and virtual memory, and finish with
static and shared libraries.

Topics
------

* Processes and the virtual address space: user space vs. kernel space
* Segments: ``.text``, ``.rodata``, ``.data``, ``.bss``, heap, stack, and the
  memory-mapped region
* ``static`` local variables and read-only string literals
* Common memory bugs: out of bounds, uninitialized reads, use after free,
  double free, and leaks
* Finding bugs with ``valgrind`` (and its most useful flags),
  AddressSanitizer (``-fsanitize=address``), and ``gdb``
* Registers and the memory hierarchy
* Caches: cache lines, hits and misses, and locality
* Why loop order matters for 2D arrays (row-major order)
* Virtual memory: pages, page tables, page hits, page faults, and demand
  paging
* Static (``.a``) and shared (``.so``) libraries
